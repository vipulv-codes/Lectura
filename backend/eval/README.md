# Evaluation protocol

This directory turns Lectura from "it seems to work" into numbers. Everything is
reproducible from `corpus.yaml` plus the committed datasets in `data/`; model
calls are cached under `cache/` so re-scoring is free and deterministic.

## What is measured

| Area | Metric | Needs LLM | Why this one |
|---|---|---|---|
| Retrieval | MRR@10, corpus mode | no | Primary decision metric. Single-video mode saturates (a 60-min lecture is ~120 chunks). |
| Retrieval | Hit@1, Hit@3, single-video | no | The product's actual use case. |
| Retrieval | Hit@120s / Hit@240s | no | Equal *context-seconds* budget, so 15 s and 60 s chunks are compared fairly. |
| Retrieval | Timestamp error (median, P90, ≤10 s) | no | Quality of the clickable link the student sees. |
| Retrieval | Video-Hit@k, corpus mode | no | Playlist routing. |
| Gate | AUROC, threshold at 95 % TPR, FPR | no | Whether "not covered" can be detected from the best score. |
| Index | HNSW vs exact recall | no | Shows approximate search is not a factor at this scale. |
| Generation | Citation validity | no | Fraction of `[MM:SS]` labels that were actually in the prompt. |
| Generation | Citation localised | no | First citation lands inside the gold span ± 10 s. |
| Generation | Abstention / false abstention | no | Sentinel sentence, exact prefix match. |
| Generation | Tokens, latency, cost/query | no | From `usage_metadata` and `pricing.yaml` (dated). |
| Generation | Faithfulness, correctness | judge | Judge audited blind against a person on 37 answers: 97.3 % agreement, and it errs strict. |
| ASR | WER (pooled), RTF, hallucination loops | no | Justifies the default Whisper model and quantifies the fallback path. |
| ASR → retrieval | Hit@3 on Whisper transcripts vs captions | no | "WER x % costs y pp of retrieval" links the two. |

Dropped on purpose: nDCG (binary relevance, one gold per query → same information as MRR) and
Recall@k (the number of "relevant chunks" depends on chunking, so it is not chunking-independent).

## Gold labels

Gold is a **video id plus timestamp span(s)**, never a chunk id (`gold.py`). A chunk is a hit when it
comes from the right video and its speech extent overlaps a gold span by ≥ 5 s (or ≥ half the span
if the span is shorter than 10 s). `anchor` is the start of the first evidence line: the timestamp a
correct clickable citation should point at.

Three sets under `data/`:

- `human.jsonl` (headline set, 60): questions drafted from transcript windows, gold lines verified by a
  person reading the transcript window (not by using the app, which would bias toward what the retriever
  already finds). Multiple spans allowed; lecturers repeat themselves.
- `synthetic.jsonl` (223): generated by `make_synthetic.py` from 120 s windows with Gemini, filtered
  deterministically (evidence labels must exist, span ≤ 60 s, no near-duplicates) and by a second
  yes/no pass. Tagged with lexical-overlap tercile, `bm25_easy`, position and course so the report can
  show that gains are not artefacts of copy-paste questions. Caveat: generated by the same model
  family that answers; retrieval metrics are unaffected (no LLM in that loop), judged correctness is
  mildly self-serving. That is why the human set is the headline.
- `unanswerable.jsonl` (30): 16 hand-written in-domain questions the corpus does not cover, plus 14
  *video-swap negatives* (a human question asked against a different video of the same course;
  guaranteed unanswerable, in-domain, hard, free).

JSONL schema:

```json
{"qid": "h_017", "set": "human", "question": "...", "short_answer": "...",
 "video_id": "abc123XYZ00", "spans": [{"start": 1834.2, "end": 1861.0}],
 "anchor": 1834.2, "tags": {"course": "cs229-2018", "position": "late"}}
```

## Pre-registered decision rules

Written before any ablation ran:

1. A default is changed only if synthetic **corpus-mode MRR@10** improves with a paired-bootstrap
   95 % CI that excludes zero **and** the human set does not move the other way.
2. Ties go to the cheaper configuration (fewer parameters, less latency).
3. Chunk size is decided on **Hit@120s**, not Hit@k, because Hit@k favours large windows trivially.
4. The relevance gate threshold is the score at 95 % TPR on answerable queries; it is adopted if FPR on
   unanswerable queries drops below 50 % at that threshold.
5. Every run stays in `RESULTS.md`, including the ones that lost.

Minimum detectable effect (difference of proportions, paired, p≈0.5): roughly 20 pp at n=50 and
8 pp at n=300. Consequence: synthetic decides, human confirms the sign and provides the headline.

## Running it

```bash
cd backend && .\venv\Scripts\activate           # or source venv/bin/activate
cp .env.example .env                           # add GEMINI_API_KEY

python -m eval.build_corpus probe               # resolve playlists, verify manual captions
python -m eval.build_corpus ingest              # transcripts + baseline index into eval/data_dir
python -m eval.make_human_draft                 # windows to write human questions against
python -m eval.make_synthetic generate          # ~700 Gemini calls, cached
python -m eval.make_synthetic swaps --n 15      # video-swap negatives from the human set

python -m eval.run_retrieval --config baseline  # no LLM
python -m eval.run_retrieval --grid stage_a     # 9 indexes × 6 pipelines, ~45 min on an RTX 3060
python -m eval.run_asr --models tiny.en base.en small.en medium.en --cpu-rtf
python -m eval.run_retrieval --config baseline --data-dir eval/data_dir_asr_tiny.en --tol 3 --run-id asr_tiny_retrieval

python -m eval.run_generation --config baseline --run-id G0 --judge gemini-3-flash-preview
python -m eval.grade --run G1_tuned              # blind human audit of the judge
python -m eval.grade --build-hard-sample         # then grade its non-clean-pass verdicts
python -m eval.report                            # -> eval/RESULTS.md
```

Ablation stages: **A** retrieval grid (no LLM) → **B** gate calibration on the winner → **C** generation
(G0 baseline, G1 Stage-A winner, G2 +gate, G3 thinking off, G4 parent 240 s, G5 top_k 8; judged G0/G1/G3)
→ **D** ASR WER + degraded-transcript retrieval.

## Reproducibility

Each run writes `manifest.json`: config, git SHA, package versions, dataset SHA-256s, seed, device,
and the `model_version` string Gemini returns. HNSW construction and Gemini sampling are not
bit-reproducible; the response cache is what makes re-scoring deterministic.

## Known caveats

- Human captions are lightly edited (fillers removed), so WER against them is an upper bound; model
  comparisons share the reference and remain fair.
- Gemini prices in `pricing.yaml` carry an `as_of` date; costs are estimates at that date.
- The corpus is three courses in English with professional captions. Auto-captioned or
  non-English lectures will do worse on every axis; the ASR experiment bounds how much.
